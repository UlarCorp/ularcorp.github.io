# Кабинет сотрудника — сайт

Публичный сайт Кабинета сотрудника (мобильное приложение Ular) и маршрут его развития.
Заменяет презентацию: обновляем сайт, а не собираем слайды заново.

- Главная: `index.html` - короткая страница с прокруткой
- Презентация: `present/index.html` (https://ularcorp.github.io/present/) - слайды 16:9, стрелки, колесо, свайп, F - во весь экран, T - тема
- Дорожная карта: слайд «Маршрут развития» и `roadmap.html`, данные — `assets/roadmap.json`, код — `assets/deck.js`
- Изменения: `changes.html`, данные — `assets/changes.json` (релиз сверху, пункт `[тип, название, пояснение]`, тип `new`/`better`/`fix`, `status`: `soon` — готовится, `released` — выпущен). После релиза поменять `status` и добавить новый блок сверху
- Стили: `assets/site.css` (цвета бренда, шрифт Onest вместо Aeonik)
- Экраны: `assets/app/light/` и `assets/app/dark/` — снимки приложения с демо-данными, сайт показывает их в своей теме

Сборки нет: обычные HTML, CSS и JS, публикуются через GitHub Pages из ветки `main`: https://ularcorp.github.io/

## Как обновить дорожную карту

Маршрут на главной, в презентации и на `roadmap.html` строится из одного файла `assets/roadmap.json`:

- `updated` - дата обновления;
- `milestones` - остановки маршрута по порядку: `date`, `version`, `title`, `status` и `items`;
- `status`: `done` - уже у сотрудников, `next` - следующее обновление, `plan` - впереди;
- пункт - пара `["Название", "Пояснение в одну строку"]`.

Вышел релиз - поменять у его остановки `status` на `done`, `date` на месяц выхода, добавить следующую остановку
со статусом `next` и обновить `updated`. «Мы здесь» и счетчики считаются сами.
Кнопки «Скачать PDF» (печать страницы) и «Скачать для Excel» (CSV) берут те же данные.

На публичном сайте не писать внутреннее: адреса серверов, сертификаты, ключи, названия баз и веток.

## Проверить локально

```
py -m http.server 8091
```

и открыть `http://127.0.0.1:8091/` (дорожная карта читает JSON, поэтому прямое открытие файла не подойдет).
